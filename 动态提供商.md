# 动态提供商架构设计

## 概述

本架构基于 LangChain 的统一接口，通过在数据库中存储 TypeScript 工厂代码字符串来动态创建不同厂商的 ChatModel 实例，实现高度灵活的厂商扩展能力。

## 角色定位

| 角色 | 职责 |
|------|------|
| **开发者** | 编写厂商工厂代码，存入数据库。需理解 LangChain 接口和各厂商协议差异 |
| **用户** | 选择厂商 + 填写 API Key，无需关心底层实现 |

**动态代码的意义**：
- 新增厂商无需发版，直接插入数据库
- 厂商协议变更，直接更新数据库中的代码
- 开发者可控，用户无感知

## 核心设计

#### Provider 表（提供商表）

| 字段 | 类型 | 说明 |

### 2. LangChain 流式处理机制

LangChain 的 `BaseChatModel` 内置了流式方法 `stream()`，但**各厂商的流式协议差异由各自的 ChatModel 类内部实现**：

```typescript
// ChatOpenAI 内部实现（简化示意）
class ChatOpenAI extends BaseChatModel {
  async *_stream(messages) {
    // 1. 发送 OpenAI 格式的请求
    const response = await fetch('https://api.openai.com/v1/chat/completions', {
      body: JSON.stringify({ stream: true, messages, model })
    })
    
    // 2. 解析 OpenAI 的 SSE 格式
    for await (const line of response.body) {
      if (line.startsWith('data: ')) {
        const data = JSON.parse(line.slice(6))
        // 3. yield 统一的 AIMessageChunk
        yield new AIMessageChunk({ content: data.choices[0].delta.content })
      }
    }
  }
}
```

**关键点**：
- `ChatOpenAI` 内部实现了 OpenAI 的 SSE 流式解析
- `ChatAnthropic` 内部实现了 Anthropic 的流式协议
- `ChatOllama` 内部实现了 Ollama 的流式处理
- 工厂返回的 ChatModel 实例已封装好流式逻辑

### 3. 思考链（Reasoning）支持

**重要限制**：`ChatOpenAI` 不会提取或保留第三方提供商的非标准字段。

| 厂商 | 思考链字段 | ChatOpenAI 支持 |
|------|-----------|----------------|
| OpenAI o1 | 官方 `reasoning` API | ✅ 通过 `reasoning` 参数 |
| DeepSeek R1 | `reasoning_content` | ❌ 会丢失 |
| 其他兼容厂商 | 各不相同 | ❌ 会丢失 |

**解决方案**：
1. 有 LangChain 官方包的用官方包（如 `ChatAnthropic`）
2. 无官方包但兼容 OpenAI API 的，用 `ChatOpenAI` + `baseUrl`
3. 需要思考链等非标准字段的，需自定义 `BaseChatModel` 实现

### 4. 工厂接口定义

```typescript
import { BaseChatModel } from '@langchain/core/language_models/chat_models'

interface VendorFactory {
  createChatModel(params: {
    model: string
    apiKey?: string
    baseUrl?: string
    config?: Record<string, unknown>
  }): BaseChatModel
}
```

### 5. 核心服务

#### DynamicCodeExecutor

负责编译和执行 TypeScript 代码：

- **transpile**: 将 TS 代码转译为 JS
- **validate**: 验证代码语法
- **execute**: 执行 JS 代码并返回导出对象
- **validateWithZod**: 使用 Zod 进行运行时校验

#### VendorService

厂商管理服务：

- **list**: 获取所有厂商
- **get**: 获取单个厂商
- **create**: 创建厂商（自动验证代码）
- **update**: 更新厂商
- **delete**: 删除厂商
- **getFactory**: 编译并返回厂商工厂对象

#### ProviderService

提供商管理服务：

- **list**: 获取所有提供商
- **get**: 获取单个提供商
- **createChatModel**: 创建 LangChain ChatModel 实例
- **create**: 创建提供商
- **update**: 更新提供商
- **delete**: 删除提供商

### 6. Zod 校验机制

#### 工厂接口校验 Schema

```typescript
import { z } from 'zod'

const CreateChatModelParamsSchema = z.object({
  model: z.string(),
  apiKey: z.string().optional(),
  baseUrl: z.string().optional(),
  config: z.record(z.unknown()).optional(),
})

const VendorFactorySchema = z.object({
  createChatModel: z.function()
    .args(CreateChatModelParamsSchema)
    .returns(z.any()), // BaseChatModel 实例
})
```

#### 包装校验

在 `validateWithZod` 中创建包装函数，确保：
1. 调用前验证输入参数
2. 返回的对象是 BaseChatModel 实例
3. 校验失败抛出详细错误信息

## 使用流程

### 1. 创建厂商（开发者操作）

在数据库中插入厂商工厂代码：

```typescript
const vendorService = new VendorService({ prisma })

await vendorService.create({
  name: 'OpenAI',
  code: `
    const { ChatOpenAI } = require('@langchain/openai')
    
    const factory = {
      createChatModel(params) {
        const { model, apiKey, baseUrl, config } = params
        return new ChatOpenAI({
          model,
          apiKey,
          configuration: {
            baseURL: baseUrl,
          },
          ...config,
        })
      },
    }
    
    module.exports = factory
  `,
})
```

### 2. 创建提供商（用户操作）

```typescript
const providerService = new ProviderService({ prisma })

await providerService.create({
  name: 'My OpenAI',
  vendorId: 1,
  apiKey: 'sk-xxx',
  baseUrl: 'https://api.openai.com',
})
```

### 3. 使用 LangChain 调用

```typescript
import { HumanMessage } from '@langchain/core/messages'

// 创建 ChatModel 实例
const chatModel = await providerService.createChatModel(providerId, 'gpt-4')

// 非流式调用
const response = await chatModel.invoke([
  new HumanMessage('Hello!'),
])

console.log(response.content)
```

### 4. 流式调用

```typescript
const stream = await chatModel.stream([
  new HumanMessage('Tell me a story'),
])

for await (const chunk of stream) {
  process.stdout.write(chunk.content)
}
```

## 安全机制

### 1. 代码沙箱

- 使用受限的 `require` 函数，只允许导入：
  - `@langchain/openai`
  - `@langchain/anthropic`
  - `@langchain/ollama`
  - `@langchain/core`
  - 其他 LangChain 相关包
- 使用 `new Function` 在隔离环境中执行代码
- TypeScript 编译时启用严格模式

### 2. Zod 校验

- 验证工厂对象的 `createChatModel` 方法
- 验证输入参数符合接口定义
- 验证返回对象是 `BaseChatModel` 实例

### 3. 缓存机制

- 编译结果缓存，避免重复编译
- 基于代码内容的哈希键
- 可手动清除缓存

## 扩展性

### 添加新厂商

只需在数据库中插入新的工厂代码，无需修改应用代码：

```sql
INSERT INTO vendors (name, code, is_active) VALUES (
  'Anthropic',
  '... 工厂代码 ...',
  true
);
```

### 自定义配置

支持通过 `config` 参数传递厂商特定的配置：
- 温度、top_p 等生成参数
- 自定义 headers
- 特殊认证方式
- 代理设置

## 性能优化

### 1. 编译缓存

相同代码只编译一次，后续直接使用缓存结果。

### 2. 懒加载

工厂对象在首次使用时才编译，避免启动时编译所有厂商代码。

### 3. 内存缓存

编译后的工厂对象缓存在内存中，避免重复解析。

## 错误处理

### 编译错误

- TypeScript 语法错误
- 缺少导出对象
- 方法签名不匹配

### 运行时错误

- Zod 校验失败
- 工厂方法执行异常
- LangChain 调用失败

所有错误都会抛出详细信息，便于定位问题。

### DeepSeek R1 工厂（支持思考链）

需要自定义 `BaseChatModel` 以提取 `reasoning_content`：

```typescript
const { BaseChatModel } = require('@langchain/core/language_models/chat_models')
const { AIMessageChunk, AIMessage } = require('@langchain/core/messages')
const { ChatGenerationChunk, ChatResult } = require('@langchain/core/outputs')

class DeepSeekR1ChatModel extends BaseChatModel {
  constructor(params) {
    super(params)
    this.config = params
  }

  _llmType() {
    return 'deepseek-r1'
  }

  async _generate(messages, options) {
    const response = await fetch(`${this.config.baseUrl}/chat/completions`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${this.config.apiKey}`,
      },
      body: JSON.stringify({
        model: this.config.model,
        messages: messages.map(m => ({ role: m._getType(), content: m.content })),
        stream: false,
      }),
    })
    
    const data = await response.json()
    
    return new ChatResult({
      generations: [{
        text: data.choices[0].message.content,
        message: new AIMessage({
          content: data.choices[0].message.content,
          additional_kwargs: {
            reasoning_content: data.choices[0].message.reasoning_content,
          },
        }),
      }],
    })
  }

  async *_stream(messages) {
    const response = await fetch(`${this.config.baseUrl}/chat/completions`, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json',
        'Authorization': `Bearer ${this.config.apiKey}`,
      },
      body: JSON.stringify({
        model: this.config.model,
        messages: messages.map(m => ({ role: m._getType(), content: m.content })),
        stream: true,
      }),
    })

    for await (const line of response.body) {
      const str = line.toString()
      if (!str.startsWith('data: ')) continue
      
      const data = JSON.parse(str.slice(6))
      if (data.choices?.[0]?.delta) {
        const delta = data.choices[0].delta
        
        // 先 yield 思考内容
        if (delta.reasoning_content) {
          yield new ChatGenerationChunk({
            message: new AIMessageChunk({
              content: delta.reasoning_content,
              additional_kwargs: { type: 'reasoning' },
            }),
          })
        }
        
        // 再 yield 正式内容
        if (delta.content) {
          yield new ChatGenerationChunk({
            message: new AIMessageChunk({ content: delta.content }),
          })
        }
      }
    }
  }
}

const factory = {
  createChatModel(params) {
    return new DeepSeekR1ChatModel(params)
  },
}

module.exports = factory
```

## 与现有代码的集成

### CutModelService 改造

```typescript
export class CutModelService {
  private prisma: PrismaClient
  private sessionService: SessionService
  private vendorService: VendorService

  constructor({ prisma, sessionService }: { prisma: PrismaClient; sessionService: SessionService }) {
    this.prisma = prisma
    this.sessionService = sessionService
    this.vendorService = new VendorService({ prisma })
  }

  private async createChatModel(model: Model, provider: Provider): Promise<BaseChatModel> {
    const factory = await this.vendorService.getFactory(provider.vendorId)
    return factory.createChatModel({
      model: model.name,
      apiKey: provider.apiKey,
      baseUrl: provider.baseUrl,
      config: model.config,
    })
  }

  private async callLLM(
    prompt: string,
    systemPrompt: string,
    model: Model,
    provider: Provider,
    sessionId: number
  ): Promise<string> {
    const chatModel = await this.createChatModel(model, provider)

    await this.sessionService.addMessage({
      sessionId,
      role: 'system',
      content: systemPrompt,
    })

    await this.sessionService.addMessage({
      sessionId,
      role: 'user',
      content: prompt,
    })

    const response = await chatModel.invoke([
      new SystemMessage(systemPrompt),
      new HumanMessage(prompt),
    ])

    const content = response.content.toString()

    await this.sessionService.addMessage({
      sessionId,
      role: 'assistant',
      content,
      metadata: { model: model.name },
    })

    return content
  }
}
```

## 优势总结

1. **统一接口**: 使用 LangChain 的 `BaseChatModel` 接口，所有厂商调用方式一致
2. **动态扩展**: 新增厂商只需插入数据库代码，无需修改应用代码
3. **类型安全**: 通过 Zod 校验确保运行时类型正确
4. **易于维护**: 厂商代码独立存储，便于更新和管理
5. **性能优化**: 编译缓存和懒加载机制，减少性能开销
6. **开发者可控**: 厂商代码由开发者维护，用户无需关心底层实现
