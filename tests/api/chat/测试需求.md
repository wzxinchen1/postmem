# Chat 接口测试需求

## 测试范围

**仅测试 `POST /api/chat/completions` 和 `POST /api/chat/cancel` 接口**（需求文档第五章"聊天完成"）。

不测试的内容：
- 对话 CRUD（`conversations.test.ts` — 已删除）
- 消息查询（`messages.test.ts` — 已删除）
- 新会话创建（不传 `newConversation=true`）

## 测试策略

### 核心原则

1. **只测 chat 相关接口**：测试用例调用 `POST /api/chat/completions` 和 `POST /api/chat/cancel`，不测其他接口
2. **始终不传 `conversationId`**：每次聊天都不传已有对话 ID，测试接口的默认行为
3. **不传 `newConversation=true`**：不显式创建新会话，测试需求 5.1 中的默认行为——既无 `conversationId` 也无 `newConversation` 时，获取最新已有对话继续聊天；若无任何对话则自动创建新对话
4. **不测其他接口**：对话 CRUD、消息查询等不在测试范围内
5. **顺序执行**：所有用例合并在单个测试文件中，使用 `describe.sequential` 保证按顺序执行，利用前序用例创建的数据
6. **只在 `beforeAll` 清空一次数据库**：后续用例利用已有数据，不再重复清空

### 执行顺序与数据依赖

```
beforeAll: cleanupConversations() → 清空数据库，获取 kbId / modelId

用例1: 空库聊天 → 自动创建新对话，验证 ChatResult 有效 + total=1 证明确实是新建，保存 firstConversationId
用例2: 不 cleanup → 聊天 → 验证复用对话（firstConversationId 一致）
用例3-5: 400 错误用例，不依赖数据
用例6-9: 流事件用例，利用已有对话数据
用例10: 取消测试，fetch 触发 + StreamReader 消费，500ms 后 cancel
用例11: cancel 400 错误用例

afterAll: client.disconnect()
```

### 测试用例

#### 一、基本功能（需求 5.1）

| # | 用例 | 说明 | 断言 |
|---|------|------|------|
| 1 | 空库时聊天 — 自动创建新对话并返回有效 ChatResult | `beforeAll` 已清空数据库，不传 `conversationId` | `conversationId` 非空 + `fullContent` 非空 + `promptTokens > 0` + `completionTokens > 0` + `listConversations().total === 1` 且 ID 匹配 |
| 2 | 默认行为 — 有对话时复用最新对话 | 不 cleanup，直接聊天 | `conversationId === firstConversationId`（复用用例 1 创建的对话） |
| 3 | 缺少 `modelId` 返回 400 | `modelId` 为空 | HTTP 400 |
| 4 | 缺少 `kbId` 返回 400 | `kbId` 为空 | HTTP 400 |
| 5 | 缺少 `messages` 返回 400 | 请求体无 `messages` 字段 | HTTP 400 |

#### 二、流事件序列（需求 5.3）

| # | 用例 | 说明 | 断言 |
|---|------|------|------|
| 6 | 首 token 时间 ≤ 10s | 从发起请求到收到第一个 chunk 的时间 | `firstChunkTime > 0` + `ttfb ≤ 10000ms` |
| 7 | 流事件包含 `chunk → usage → done` 序列 | 验证事件顺序 | `indexOf('chunk') < indexOf('usage') < indexOf('done')` |
| 8 | 流事件包含 `messageId`（user + assistant） | 至少包含 `role=user` 和 `role=assistant` 的 messageId | `messageIdEvents.length >= 2` + 存在 user 和 assistant 两种 role |
| 9 | 流事件包含 `status` 事件 | 验证聊天流程中推送了状态通知 | `statusEvents.length >= 1` |

#### 三、取消聊天（需求 5.4）

| # | 用例 | 说明 | 断言 |
|---|------|------|------|
| 10 | 取消进行中的对话 | fetch 触发聊天 → StreamReader 消费 → 等 500ms → cancel | 流事件包含 `done` |
| 11 | 缺少 `conversationId` 返回 400 | cancel 请求无 conversationId | HTTP 400 |

### 实现要点

- **单文件**：所有用例在 `completions.test.ts` 中，`cancel.test.ts` 已删除
- **`describe.sequential`**：保证用例按书写顺序执行
- **`vitest.config.ts` 设置 `fileParallelism: false`**：防止文件间并行
- **用例 1 的空库验证**：`beforeAll` 已 cleanup，聊天后通过 `listConversations()` 验证数据库只有 1 个对话且 ID 匹配，证明确实是新建而非复用
- **用例 10 的取消实现**：使用 `client.chat()` 触发聊天后立即返回 `ChatHandle`，等 500ms 后调用 `client.cancel(handle.conversationId)`，最后 `await handle.done` 等待流结束并验证结果
