# 字节豆包 API 协议

## 1. 基础请求格式

字节豆包 API 兼容 OpenAI API 格式,通过火山方舟平台提供服务:

```http
POST /api/v3/chat/completions HTTP/1.1
Host: ark.cn-beijing.volces.com
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "model": "doubao-pro-32k",
  "messages": [
    {"role": "user", "content": "解释计算机视觉的应用场景"}
  ],
  "stream": true,
  "temperature": 0.7
}
```

**关键参数说明**:

| 参数 | 类型 | 说明 |
|------|------|------|
| `model` | string | 模型 ID,如 `doubao-pro-32k`、`doubao-1.5-pro-32k` |
| `messages` | array | 对话消息数组 |
| `stream` | boolean | 是否开启流式输出(推荐 `true`) |
| `temperature` | number | 生成随机性(0-1,值越大越随机) |
| `max_tokens` | number | 最大生成 token 数(快速模型) |

**可用模型列表**:

| 模型 ID | 上下文窗口 | 输出限制 | 说明 |
|---------|-----------|---------|------|
| `doubao-pro-32k` | 32k | 4k | 标准版 |
| `doubao-pro-128k` | 128k | 4k | 长上下文版 |
| `doubao-1.5-pro-32k` | 32k | 4k | 1.5版本 |
| `doubao-1.5-pro-256k` | 256k | 8k | 超长上下文 |
| `doubao-1.5-lite-32k` | 32k | 4k | 轻量版 |
| `doubao-seed-1-6-flash-250615` | 32k | 4k | 快速思考模型 |
| `doubao-seed-1-6-thinking-250715` | 128k | 65k | 深度思考模型 |

## 2. 深度思考模式(Thinking Mode)

豆包深度思考模型支持类似 OpenAI o1 系列的思考链功能:

```http
POST /api/v3/chat/completions HTTP/1.1
Host: ark.cn-beijing.volces.com
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "model": "doubao-seed-1-6-thinking-250715",
  "messages": [
    {"role": "user", "content": "请分析:为什么天空是蓝色的?"}
  ],
  "thinking": {
    "type": "auto"  // auto:自动判断是否需要思考
  },
  "max_output_tokens": 10000,  // 使用 max_output_tokens 控制总长度(含思考)
  "stream": true
}
```

**深度思考参数说明**:

| 参数 | 类型 | 说明 |
|------|------|------|
| `thinking.type` | string | 思考模式:`auto`(自动判断)、`enabled`(强制启用) |
| `max_output_tokens` | number | 总 token 数(思考+回答),最大 65536 |
| `instructions` | string | 替代 system 消息的指令 |

**关键差异对比**:

| 对比维度 | 快速思考模型 | 深度思考模型 |
|---------|-------------|-------------|
| **模型 ID** | `doubao-seed-1-6-flash-250615` | `doubao-seed-1-6-thinking-250715` |
| **Token 控制** | `max_tokens` | `max_output_tokens`(最大 65536) |
| **特殊参数** | 无 | `thinking`、`max_output_tokens`、`instructions` |
| **响应结构** | `choices[0].message.content` | `output` 数组(含 `reasoning` 和 `message`) |

**重要说明**:
- ⚠️ 深度思考模型的思考过程在 API 响应中**可见**(与 OpenAI o1 不同)
- ⚠️ 响应中会包含 `reasoning` 类型的内容块,展示思考过程
- ⚠️ 使用 `max_output_tokens` 而非 `max_tokens` 控制总长度
- ⚠️ 深度模型响应结构不同,需从 `output` 数组解析

## 3. 流式响应报文示例

### 3.1 快速模型流式响应

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

// 第一个数据块:包含角色信息
data: {"id":"xxx","object":"chat.completion.chunk","created":1234567890,"model":"doubao-pro-32k","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

// 后续数据块:逐步返回内容
data: {"id":"xxx","object":"chat.completion.chunk","created":1234567890,"model":"doubao-pro-32k","choices":[{"index":0,"delta":{"content":"计"},"finish_reason":null}]}

data: {"id":"xxx","object":"chat.completion.chunk","created":1234567890,"model":"doubao-pro-32k","choices":[{"index":0,"delta":{"content":"算"},"finish_reason":null}]}

// ... 更多内容

// 最后一个数据块:标记结束
data: {"id":"xxx","object":"chat.completion.chunk","created":1234567890,"model":"doubao-pro-32k","choices":[{"index":0,"delta":{},"finish_reason":"stop"}],"usage":{"prompt_tokens":10,"completion_tokens":100,"total_tokens":110}}

// 最终结束标记
data: [DONE]
```

### 3.2 深度思考模型流式响应

```http
HTTP/1.1 200 OK
Content-Type: text/event-stream
Cache-Control: no-cache
Connection: keep-alive

// 思考过程开始
data: {"output":[{"type":"reasoning","content":[{"type":"text","text":"让我思考一下这个问题..."}]}]}

// 思考过程继续
data: {"output":[{"type":"reasoning","content":[{"type":"text","text":"\n\n天空呈现蓝色是因为瑞利散射现象:\n1. 太阳光包含多种颜色\n2. 大气分子散射短波长光\n3. 蓝光波长较短,散射更强"}]}]}

// 最终回答开始
data: {"output":[{"type":"message","content":[{"type":"text","text":"天空呈现蓝色主要是由瑞利散射现象导致的。"}]}]}

// 最终回答继续
data: {"output":[{"type":"message","content":[{"type":"text","text":"\n\n**瑞利散射原理**:大气中的分子会散射太阳光中的短波长成分..."}]}]}

// ... 更多内容

// 结束标记
data: {"output":[],"finish_reason":"stop","usage":{"prompt_tokens":20,"completion_tokens":500,"total_tokens":520}}
```

**字段说明**:
- `output[].type`: 内容类型,`reasoning`(思考过程)或 `message`(最终回答)
- `output[].content[].text`: 文本内容
- `finish_reason`: 结束原因(`stop`/`length`/`null`)
- `usage`: Token 使用统计

## 4. Function Calling(工具调用)

豆包 API 支持标准的 Function Calling 功能:

```http
POST /api/v3/chat/completions HTTP/1.1
Host: ark.cn-beijing.volces.com
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "model": "doubao-pro-32k",
  "messages": [
    {"role": "user", "content": "北京今天天气怎么样?"}
  ],
  "tools": [
    {
      "type": "function",
      "function": {
        "name": "get_weather",
        "description": "获取指定城市的天气信息",
        "parameters": {
          "type": "object",
          "properties": {
            "city": {
              "type": "string",
              "description": "城市名称"
            }
          },
          "required": ["city"]
        }
      }
    }
  ],
  "tool_choice": "auto"
}
```

**工具调用响应**:

```json
{
  "id": "chatcmpl-xxx",
  "object": "chat.completion",
  "created": 1234567890,
  "model": "doubao-pro-32k",
  "choices": [
    {
      "index": 0,
      "message": {
        "role": "assistant",
        "content": null,
        "tool_calls": [
          {
            "id": "call_abc123",
            "type": "function",
            "function": {
              "name": "get_weather",
              "arguments": "{\"city\":\"北京\"}"
            }
          }
        ]
      },
      "finish_reason": "tool_calls"
    }
  ]
}
```

**工具调用流程**:
1. 模型返回 `tool_calls`,包含函数名和参数
2. 开发者执行实际函数调用
3. 将函数结果作为新消息添加到 `messages`
4. 再次调用 API 获取最终回答

```http
POST /api/v3/chat/completions HTTP/1.1
Host: ark.cn-beijing.volces.com
Authorization: Bearer YOUR_API_KEY
Content-Type: application/json

{
  "model": "doubao-pro-32k",
  "messages": [
    {"role": "user", "content": "北京今天天气怎么样?"},
    {"role": "assistant", "tool_calls": [{"id": "call_abc123", "type": "function", "function": {"name": "get_weather", "arguments": "{\"city\":\"北京\"}"}}]},
    {"role": "tool", "tool_call_id": "call_abc123", "name": "get_weather", "content": "北京今天晴,温度25°C"}
  ]
}
```

## 8. 错误处理

### 常见错误码

| 错误码 | 说明 |
|--------|------|
| 401 | 认证失败,API Key 无效 |
| 404 | 模型不存在或 Endpoint 配置错误 |
| 400 | 请求参数错误 |
| 429 | 请求频率超限 |
| 500 | 服务器内部错误 |

### 错误响应格式

```json
{
  "error": {
    "code": "invalid_request_error",
    "message": "模型 ID 不存在",
    "type": "invalid_request"
  }
}
```

## 9. SDK 使用示例

### 9.1 Node.js SDK

```javascript
const { VolcEngineArkApi, ApiClient } = require('@volcengine/ark');

// 初始化客户端
const client = new ApiClient({
  accessKeyId: '你的 AccessKey',
  secretAccessKey: '你的 SecretKey',
  region: 'cn-beijing',
});

const api = new VolcEngineArkApi(client);

// 非流式调用
async function chat() {
  const response = await api.createChatCompletion({
    model: 'doubao-pro-32k',
    messages: [{ role: 'user', content: '你好' }],
    temperature: 0.7,
  });
  console.log(response.choices[0].message.content);
}

// 流式调用
async function streamChat() {
  const stream = await api.createChatCompletionStream({
    model: 'doubao-pro-32k',
    messages: [{ role: 'user', content: '写一首诗' }],
    stream: true,
  });

  for await (const chunk of stream) {
    process.stdout.write(chunk.choices[0]?.delta?.content || '');
  }
}
```

### 9.2 Python SDK

```python
from volcengine.ark import ArkService

# 初始化服务
ark_service = ArkService(
    api_key='YOUR_API_KEY',
    base_url='https://ark.cn-beijing.volces.com/api/v3'
)

# 非流式调用
response = ark_service.chat_completion(
    model='doubao-pro-32k',
    messages=[{'role': 'user', 'content': '你好'}]
)
print(response.choices[0].message.content)

# 流式调用
stream = ark_service.stream_chat_completion(
    model='doubao-pro-32k',
    messages=[{'role': 'user', 'content': '写一首诗'}],
    stream=True
)

for chunk in stream:
    if chunk.choices[0].delta.content:
        print(chunk.choices[0].delta.content, end='', flush=True)
```

## 10. 最佳实践

### 10.1 API Key 获取

1. 访问火山方舟平台: https://console.volcengine.com/ark
2. 创建推理接入点并获取 Endpoint
3. 在 API Key 管理页面创建密钥
4. 记录模型 ID(如 `doubao-pro-32k`)

### 10.2 流式输出优化

- ✅ 推荐开启 `stream: true`,实现逐字输出
- ✅ 使用 SSE(Server-Sent Events)处理流式数据
- ✅ 前端使用 Fetch API + ReadableStream 或自定义 EventSource

### 10.3 深度思考模型使用建议

**推荐场景**:
- 复杂数学推理
- 逻辑分析问题
- 多步骤任务规划
- 代码调试与优化

**不推荐场景**:
- 简单问答
- 创意写作
- 翻译任务

### 10.4 Token 成本优化

- 使用上下文缓存功能
- 合理设置 `max_tokens`/`max_output_tokens`
- 根据场景选择合适的模型(快速模型 vs 深度模型)
